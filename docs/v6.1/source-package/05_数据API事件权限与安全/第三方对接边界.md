# 第三方对接边界

## 一、微信小程序

平台通过微信开放平台能力管理商家自有 AppID。商家本人完成授权，乐趣宝保存授权范围和密钥引用，不保存可直接展示的明文密钥。

标准流程：商家选名称和模板 → 授权 AppID → 生成配置 → 构建体验版 → 商家确认 → 上传代码 → 提交审核 → 接收审核结果 → 发布 → 健康检查 → 升级或回退。审核时长、驳回和类目资质属于外部依赖，必须在界面中单独展示。

微信回调先验签、落原始加密载荷对象存储、按外部事件编号去重，再异步更新状态。授权撤回后立即停止上传、发布和读取受限数据，并通知商家重新授权。

## 二、企业微信

V1 可用范围：员工授权登录、组织内身份映射、内部接单提醒、打开乐趣宝移动工作台。企业微信提醒失败时，乐趣宝站内队列仍然保留任务。

V1 明确不做：冒充员工自动回复其个人微信或外部联系人、绕过平台规则批量发消息、把企业微信群当作商家小程序在线客服的唯一会话通道。商家小程序里的客户咨询由自研在线客服处理，员工在乐趣宝接管。

## 三、自研在线客服

消费者端嵌入商家小程序，可采用 WebSocket 加短轮询降级。消息先持久化再返回消息 ID；AI 回复、知识检索、工具调用和人工路由异步执行。员工端订阅自己有权限的门店队列。

AI 只能调用经过权限声明的工具。退款、赔付、投诉、食品安全等高风险动作创建人工工单。客户离开小程序后，只有取得相应授权时才能发送订阅消息邀请其返回，不得未经同意触达。

## 四、支付

消费者交易资金直接进入商家自己的支付账户。平台以服务商或技术接入方身份创建支付凭证、接收回调和提供对账，不把消费者交易款计入平台可用余额。

支付和退款回调必须验签，以渠道交易号去重。前端支付结果只用于展示“正在确认”，最终结果来自回调或主动查询。平台订阅费、渠道手续费、商家促销出资和消费奖励分别记账。

## 五、GEO 发布目标

每个目标使用独立适配器，统一实现 `validate`、`publish`、`query_status`、`revoke`。适配器输出标准错误码：授权失效、限流、资料无效、目标不可用和未知错误。

可承诺资料结构化、发布、一致性检查和健康提醒；不承诺任何第三方一定收录、排序位置或流量。

## 六、模型网关

业务服务只调用平台模型网关，不直接绑定单一模型供应商。网关负责租户额度、模型路由、超时、成本记录、敏感信息处理、提示词版本、工具白名单和追踪编号。

模型供应商返回的文本不能直接执行数据库写操作。所有工具调用经过参数校验、RBAC、租户范围、风险规则和幂等处理。对话正文是否发送给上游由隐私说明、数据等级和供应商协议共同决定。

## 七、插件运行时

插件清单声明权限、资源范围、外部域名、事件订阅、费用、数据保留和卸载动作。运行时发放短时租户令牌，只包含用户已批准的权限；插件不能读取平台主密钥或其他租户数据。

V1 只开放审核通过的第一方插件。增加权限、外部域名或敏感数据访问时必须作为新版本重新审核和授权。插件连续超时或异常访问时自动熔断，不能阻塞订单、支付和客服主流程。

## 八、所有适配器共同要求

- 请求超时、连接超时和总时限分别配置；禁止无限等待。
- 写请求使用业务幂等键，响应保存外部请求编号和脱敏摘要。
- 只对明确可重试错误自动重试；认证、资质和参数错误转人工。
- 每个外部调用携带 `trace_id`，记录耗时、结果码和限流信息。
- 沙箱、测试和生产账户完全隔离，密钥由密钥管理服务保存和轮换。
- 外部接口版本升级先在试点租户灰度，保留回退适配器。
