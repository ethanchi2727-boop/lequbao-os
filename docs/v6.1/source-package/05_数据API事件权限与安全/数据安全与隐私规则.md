# 数据安全与隐私规则

本文件是产品和研发默认规则，正式上线前仍需根据实际经营地区、行业、合同和第三方协议完成法律审查。

## 一、数据分类

| 等级 | 例子 | 默认控制 |
|---|---|---|
| PUBLIC | 已公开门店名称、营业时间、公开商品 | 可用于商家小程序和 GEO 发布，但变更仍需商家确认 |
| INTERNAL | 交付进度、模板版本、系统指标 | 登录、租户隔离、最小权限 |
| PERSONAL | 昵称、手机号、订单、聊天记录、位置 | 明确用途、加密、脱敏、访问审计、到期处理 |
| SENSITIVE | 证件、支付密钥、精确位置、高风险投诉材料 | 单独授权或必要依据、字段级加密、双人审批、严禁日志明文 |

## 二、持续客户档案

持续客户档案用于在同一商家范围内连续服务客户，不是永久记忆。档案只保存经告知且与服务有关的事实，例如客户主动提供的偏好、历史订单、已解决问题和授权状态。

每条档案信息保存来源、租户、用途、生成方式、置信度、最后确认时间和到期时间。客户可以查看、更正、撤回相关同意或申请删除。撤回后停止继续生成个性化档案；法定或交易必要记录按适用要求保留，但不再用于营销或个性化。

不同商家的客户档案严格分开。平台不得把 A 商家的聊天、订单或偏好提供给 B 商家，也不得用于训练公共模型，除非另有清晰、有效和可撤回的授权及合规依据。

## 三、告知与同意

- 服务所必需的数据和可选个性化、营销、订阅消息、位置分别说明，不捆绑同意。
- 首次进入在线客服时显示 AI 身份、用途、可能转人工和隐私入口。
- 客户要求人工时应有明显按钮或自然语言入口，不用隐藏式交互。
- 订阅消息按具体用途申请，拒绝后仍可继续使用基本服务。
- 隐私政策版本、授权动作、时间、界面和证据引用写入不可抵赖记录。

## 四、建议保留类别

实际期限由业务、合同、行业和法律评审配置，以下是产品默认建议，不替代法定要求。

| 数据 | 默认在线保留 | 到期动作 |
|---|---:|---|
| 原始模型请求与调试响应 | 30 天 | 删除正文，仅保留脱敏指标 |
| 在线客服正文 | 会话结束后 365 天 | 删除或匿名化；投诉处理中的记录可合法延长 |
| 持续客户档案条目 | 最后确认后 365 天 | 重新确认或删除 |
| 产品埋点明细 | 180 天 | 聚合后删除明细 |
| 安全与权限审计 | 3 年 | 到期归档或删除 |
| 订单、支付、退款和对账 | 按交易、税务和适用法律配置 | 受控归档后到期删除 |
| 授权和撤回证据 | 授权有效期及争议处理所需期限 | 到期归档或删除 |
| 导出文件 | 7 天 | 自动删除对象和下载密钥 |
| 交付构建日志 | 90 天 | 删除正文，保留结果和错误码 |

“删除”应覆盖主库、搜索、向量索引、缓存和对象存储；备份中的数据按备份周期自然过期，并在恢复后重新执行删除队列。

## 五、客户权利请求

请求流程：验证身份 → 确认租户和范围 → 判断法定保留或争议冻结 → 导出、更正、限制、撤回或删除 → 记录处理结果。无法删除的交易记录要向客户说明原因，并停止非必要用途。

导出文件加密、水印、短时有效且限制下载次数。商家员工不能批量导出不属于其门店的客户数据。

## 六、加密与密钥

- 传输使用当前安全 TLS；服务间身份双向验证或签名令牌。
- 证件、手机号、地址、联系人和外部授权采用字段级信封加密；搜索使用单独带盐哈希。
- 外部密钥、支付密钥和插件密钥只保存密钥管理服务引用，不能进入数据库、日志、事件或前端包。
- 不同环境、租户高敏资源和用途使用分离密钥；记录轮换、使用和撤销。

## 七、日志和模型安全

日志默认脱敏，不记录访问令牌、验证码、支付密钥、完整手机号、完整地址、证件和聊天正文。错误页面只显示公开错误码和追踪号。

知识库和客户消息都视为不可信输入。模型提示词防止文档指令绕过权限；工具调用必须经过结构校验、权限、资源范围、风险规则和幂等处理。模型不能直接拼接 SQL、调用任意网址或读取插件未授权数据。

## 八、商家退出

商家 AppID 和主体继续归商家。平台按合同提供数据导出，建议 7 天服务宽限和 30 天导出窗口；到期后停止在线服务，并按保留规则删除或匿名化。平台模板、托管后端、通用技能和源代码不属于商家数据导出范围。
