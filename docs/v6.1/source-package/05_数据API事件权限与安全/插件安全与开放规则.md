# 插件安全与开放规则

## 一、V1 开放范围

V1 插件中心可以展示和安装插件，但只运行平台审核通过的第一方插件。第三方开发者提交、收费分成、公共市场和任意代码上传放到后续阶段。这样不影响内部不断增加好用能力，也不会把首版安全和结算难度扩大。

技能是可复用的方法、提示词、步骤和验收条件；插件是可调用的能力适配器；一键交付是调用多个插件和技能的顶层工作流。技能不能自行获得数据权限，工作流不能绕过插件权限。

## 二、插件清单

每个版本必须声明：

- 插件代码、名称、发布者和语义版本
- 请求的权限代码和门店、客户、订单等资源范围
- 订阅的事件和产生的事件
- 允许访问的外部域名、HTTP 方法和数据类别
- 密钥类型、保存位置和轮换方式
- 费用、用量单位和超额处理
- 数据保留期限、删除接口和卸载影响
- 超时、重试、幂等、降级和人工处理方式
- 包摘要、签名、依赖清单和安全扫描结果

## 三、安装授权

安装界面逐项展示权限、数据、外部域名、费用和卸载影响。商家负责人确认后生成租户安装记录。高风险权限需要双人审批。插件更新只修复代码且权限不变时可灰度升级；新增权限、域名或敏感数据必须重新授权。

运行时令牌只包含安装已批准的权限和资源范围，短时有效。插件不得使用平台管理员令牌，也不得将一个租户令牌缓存后用于另一个租户。

## 四、运行隔离

- 独立进程或受限容器，CPU、内存、并发、网络和执行时长有上限。
- 默认禁止出网，只开放清单中的 HTTPS 域名；禁止访问内网元数据地址。
- 只通过平台 API 访问业务数据，不直连主数据库。
- 文件使用租户隔离对象路径和短时签名地址。
- 事件消费使用 Inbox 去重，写操作带幂等键。
- 连续错误、超时、异常流量或越权访问自动熔断。

## 五、AI 工具权限

把插件暴露为 AI 工具时，为每个工具定义结构化输入、只读或写入属性、风险级别、所需权限和是否需要用户确认。模型提供的参数只能是候选值，服务端重新读取价格、订单、门店和客户归属。

退款、发布、批量触达、导出、成员提权、奖励规则和结算不能由模型在无确认情况下执行。工具结果返回最小必要字段，禁止把密钥或其他租户信息放进模型上下文。

## 六、审核与撤销

发布前必须通过依赖与漏洞扫描、静态规则、权限审查、越权测试、数据删除测试、性能和故障演练。撤销插件时立即停止新调用、撤回令牌、保留待处理业务任务并执行卸载数据处理。

插件下架不能使订单、支付、退款、核销和客服主流程不可用。关键能力必须由平台主服务兜底或明确阻止安装为单点依赖。

## 七、审计证据

安装、授权、更新、调用、失败、熔断、卸载和数据删除都记录租户、操作者、插件版本、权限、资源、结果和追踪号。插件自身日志不得包含完整客户正文或外部密钥。
