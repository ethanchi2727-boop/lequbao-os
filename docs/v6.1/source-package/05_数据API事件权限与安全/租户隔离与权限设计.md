# 租户隔离与权限设计

## 一、身份模型

一个自然人只有一个平台用户身份，但可以加入多个租户。每次会话必须选择当前租户，访问令牌包含 `tenant_id`、`user_id`、角色、门店范围、会话编号和过期时间。切换租户必须换取新令牌，禁止只改请求头。

商家负责人、店长、客服、财务、运营、核销员和审计员使用同一乐趣宝入口，菜单和工具根据权限显示。合作伙伴只访问平台分配给自己的商家交付项目，不自动获得商家客户、订单和财务明细。

## 二、每个请求的检查顺序

1. 验证令牌签名、有效期、会话撤销状态和多因素要求。
2. 从服务端令牌确定租户，开启数据库事务并执行 `SET LOCAL app.tenant_id = :tenant_id`。
3. 检查角色是否拥有权限代码。
4. 检查资源是否属于当前租户和授权门店；跨租户资源统一返回 404。
5. 检查套餐、订阅状态、插件授权和业务状态。
6. 高风险动作进行二次确认或双人审批。
7. 写入业务数据、Outbox 和审计记录后提交。

客户端传入的 `tenant_id`、角色、价格、奖励金额、退款上限和插件权限只作输入，不作为可信结论。

## 三、数据库隔离

- 所有业务表带 `tenant_id`，关键父子关系同时校验租户与资源 ID。
- PostgreSQL 行级安全默认开启。应用连接没有 `BYPASSRLS`，数据库表所有者不用于线上请求。
- 后台任务按租户分批运行，每次事务重新设置租户，禁止一个 ORM 会话混用多个租户。
- 平台级目录表与租户表分开。全局插件目录不含租户经营数据。
- 缓存键、对象存储路径、搜索索引和向量库命名空间都以租户 ID 开头。
- 测试环境使用两个租户交叉构造相同订单号、客户昵称和门店编码，验证无串读、串写和串缓存。

## 四、权限解释

`RBAC矩阵.csv` 中的值：

- `ALL`：平台范围，仅限专用管理服务。
- `TENANT`：当前租户全部门店。
- `STORE`：令牌中的门店列表。
- `ASSIGNED`：合作伙伴被平台分配的商家，默认只含交付资料。
- `OWN`：本次操作人自己创建或扫描的记录。
- `CONDITIONAL`：命中金额、时限和风险规则时转审批。
- `DUAL`：两名不同且合格的人员确认。
- `JIT_READ`：限时、限资源、说明原因的只读授权。
- `GRANT`：插件安装时商家明确批准的权限和资源范围。
- `NONE`：拒绝。

## 五、高风险操作

以下动作强制二次确认和审计：商家主体变更、AppID 授权或撤回、小程序提交和发布、批量导出、退款、奖励规则变更、财务结算、成员提权、插件安装及新增权限、客户删除、租户暂停。

双人审批要求请求人与审批人不同，审批人权限在执行时再次校验。审批超过有效期、原请求内容变化或角色被撤销后自动失效。

## 六、平台支持访问

平台客服和研发默认不能读取商家客户正文。排查必须创建限时支持单，写明租户、资源、字段范围、原因和到期时间；商家授权后发放只读访问。涉及安全事故的紧急访问走双人审批并在事后通知和复盘。

禁止“登录成商家”并隐藏真实操作者。所有支持操作显示平台操作者身份；生产数据修改走受审计的业务命令或修复脚本。

## 七、企业微信身份边界

企业微信可用于员工授权登录、组织身份映射和内部提醒。外部身份映射只提供“这个员工是谁”，不自动授予乐趣宝角色。商家负责人仍需在乐趣宝确认门店和角色。

企业微信授权不代表平台可以冒充员工回复其个人微信或外部联系人。客户消息由商家小程序内的自研在线客服接收，员工在乐趣宝移动端或 PC 端接管。

## 八、服务账户

工作流、事件消费者、报表和插件运行时使用独立服务身份，不共享管理员令牌。服务身份绑定最小权限、允许调用的服务和有效期。插件令牌还绑定安装编号、权限清单、资源范围和外部域名。

密钥轮换或服务撤销不应中断已持久化业务任务；任务重新取短时令牌后继续，旧令牌立即失效。
