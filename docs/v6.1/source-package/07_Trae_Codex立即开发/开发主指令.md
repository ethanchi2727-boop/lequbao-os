# 开发主指令

你正在开发“乐趣宝与乐趣生活”。开始写代码前，完整读取本总包，特别是冻结决定、模块需求说明书、页面树、状态机、OpenAPI、数据库、权限矩阵和测试门禁。

## 不可改变的范围

- 用户可见产品只有乐趣宝和乐趣生活。
- 商家独立小程序是共享模板实例，不是第三套长期分支。
- V1 没有飞书、AI盒子、个人微信助手、跨境、AI小游戏、批量短视频生产。
- 企业微信只做组织授权、员工身份、内部通知和乐趣宝移动入口。
- 自研 AI 客服在商家小程序里接待，员工在乐趣宝接管。
- 一键交付是有状态、可恢复的总流程，不是单个插件。
- AppID 和名称归商家，发布必须经过商家确认和微信审核。
- GEO 不承诺第三方收录、排名或客流。
- 任何套餐数字、角色、额度、功能开关都从配置和权益中心读取。

## 工程规则

1. 先给出本次变更影响清单，包括页面、接口、表、权限、事件、任务、外部平台和回滚点。
2. 先写或更新自动测试，再实现代码。
3. 登录服务生成租户上下文，任何业务接口都不相信前端 tenant_id。
4. 每张商户业务表、对象存储路径、缓存键、队列消息和向量集合都有租户边界。
5. Harness 和模型只能通过 Adapter、AI Gateway、Tool Gateway 调业务能力。
6. 写操作由业务服务再次检查角色、数据范围、对象状态、金额、套餐、确认和幂等键。
7. 外部调用通过 Outbox、Inbox、验签、去重、有限重试和异常中心处理。
8. 支付、退款、核销、结算、订阅、奖励和 AI 额度使用不同账本或状态。
9. 日志不得写完整电话、聊天、证书、Token 或支付敏感数据。
10. 每个功能提供灰度开关、监控指标和回滚方式。

## UI 规则

- 乐趣宝先完成 Harness 新对话、普通对话、复杂任务三种形态。
- 右侧“任务与成果”只在复杂任务、成果、来源集合或待确认动作时出现。
- 输入区、消息操作、身份卡和 68 项控件不能省略。
- 乐趣生活以生活消费为首页，不做导购代理首页。
- Banner 整块点击，分类有独立图标，关键按钮至少 44 像素高。
- 所有页面处理八类状态，错误要告诉用户如何继续。

## AI 客服规则

- 默认流程：识别问题、查知识和业务事实、调用只读工具、风险判断、回答或转人工。
- 退款、赔偿、改价、取消订单、大额发券和特殊承诺必须走规则或人工确认。
- 人工接管后 AI 停止对外回复，只有明确“交还AI”后恢复。
- 客户档案只在本商户内使用，摘要有来源、可信度和失效时间。
- 用户可查询、更正和申请删除非必须保留信息。
- 用户离开小程序后，只在其主动授权订阅消息时提醒返回。

## 每次交付必须附

- 影响分析。
- 测试命令和通过结果。
- 数据库迁移与回滚。
- 权限与跨租户测试。
- API 与事件兼容说明。
- 截图或端到端录像。
- 已知限制。

若需求与冻结决定冲突，停止实现，列出冲突、影响和需要业务确认的选择，不要自行扩大首发范围。
