# 立即开工说明

## 结论

产品结构可以开工。第一阶段只做两个用户可见产品：

- 乐趣宝：总部、商务、商户、员工、客服、财务共用的权限化 AI 工作台。
- 乐趣生活：消费者使用的生活消费、商城和本地团购小程序。

商家独立小程序是乐趣宝按共享模板生成的商户实例，不是第三个独立产品。

## 开发前采用的默认规则

- 898 元基础版：1 个商户主体、1 个品牌、1 家门店、1 个商户自有 AppID 的标准小程序、2 个员工账号。
- 一键交付是耐久工作流，不是插件。它调用小程序、GEO、组织、AI客服等能力。
- 商家小程序名称由商家填写，AppID 和主体归商家，必须经过微信授权与审核。
- 消费者交易资金进入商家自己的微信支付账户，平台只收软件订阅费。
- AI 客服的主入口在商家小程序，员工在乐趣宝 PC 或移动端接管。
- 企业微信首发只做组织授权、员工身份和内部通知，不代替消费者聊天，不读取员工外部私聊。
- GEO 只承诺资料整理、发布、可访问性验证、差异监测和优化，不承诺外部收录、排名或客流。
- 首发插件中心只允许平台审核的官方插件。
- 首发没有飞书、AI盒子、个人微信助手、跨境、AI小游戏和批量短视频生产。

## 第一周先做什么

1. 建 pnpm 单仓库和持续集成。
2. 起 PostgreSQL，执行 schema.sql，打开 RLS。
3. 完成租户、组织、成员、角色、套餐权益和审计。
4. 实现乐趣宝 Harness 三种页面壳，不接生产写工具。
5. 实现商家主档和一键交付状态机的空跑版本。
6. 接入事件信封、Outbox、任务重试和异常中心。
7. 把跨租户测试、重复回调测试和人工接管测试放入合并门禁。

## 不要先做

- 不要先做短视频、跨境、游戏或第三方插件交易。
- 不要为每家商户复制一套小程序代码。
- 不要让 Harness 或模型直接写业务表。
- 不要把 tenant_id 当成前端可自由传入参数。
- 不要在没有支付与奖励书面确认前迁移真实资金数据。
- 不要为了演示写死套餐权益、模型额度或角色权限。
