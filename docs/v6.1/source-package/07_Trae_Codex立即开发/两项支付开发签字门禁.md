# 两项支付开发签字门禁

产品、租户、主档、工作台、交付、小程序体验版和 AI 客服可以先开发。下面两项在接入真实消费者资金或迁移旧奖励余额前，必须由业务、财务、产品和技术共同签字。

## 1. 消费者交易资金

本总包默认方案：

- 商家独立小程序的资金直接进入商家自己的微信支付商户号，或合法的服务商子商户账户。
- 乐趣宝收 898/1980 软件订阅费，不代商家长期沉淀消费者交易资金。
- 乐趣生活平台商城、数字供应链和本地团购单独确定交易责任、开票、退款、结算和售后主体。
- 订阅费、消费者支付、退款、平台服务费、消费奖励和渠道分润分别记账。

需签字确认：

- 商家小程序采用普通商户直连还是服务商模式。
- 乐趣生活各业务场景的收款与交易责任主体。
- 手续费、退款损失、补贴和奖励由谁承担。
- 发票、结算周期和异常款处理。

## 2. 原消费奖励账本迁移

需先提供：

- 旧系统奖励余额和流水总表。
- 生成、使用、过期、退款冲正和结算规则。
- 每类余额的出资方和法律责任。
- 旧 ID 到新租户、会员和订单 ID 的映射。

迁移必须做到：

- 迁移前后总额、账户数和逐笔流水一致。
- 不按手机号直接合并有争议的身份。
- 有冻结时点、增量补迁、差异清单和回滚方案。
- 迁移演练至少两次。
- 财务签字后才切换真实账本。
