# 订单履约与售后产品需求说明书

## 模块目标

商品、团购、付款、履约、核销、退款和售后使用同一套订单规则。乐趣生活、商家独立小程序和乐趣宝看到的是同一订单，不复制账目。

## 订单类型

首发支持实物配送、到店自提、到店团购核销和一般服务预约。每种类型有独立履约字段，但共用金额、优惠、支付、退款和审计规则。

## 创建订单

服务端重新检查商品状态、价格、库存、适用门店、购买限制和优惠。前端传来的金额不能直接作为应收金额。

创建成功后返回唯一订单号和支付超时时间。相同用户、相同购物内容和相同幂等键不能重复创建订单。

跨商家购物车按商家拆成多个订单。每个订单单独计算运费、优惠、退款和结算。

## 支付

消费者经营款进入商户自己的支付账户。支付回调必须验签并可重复接收，重复回调不能重复发货、发券或发放消费奖励。

前端支付成功但服务端尚未确认时显示“确认中”。系统主动查询支付结果，不能让消费者反复付款。

## 履约和核销

实物订单记录备货、发货、物流和签收。自提订单记录门店、取货时间和取货码。团购订单生成独立核销凭证。

核销员只能核销被授权门店的有效凭证。核销动作检查状态、门店、时间、次数和设备风险。成功后立即写入不可重复的核销记录。

误核销进入撤销申请，由店长或更高权限审批。系统不能直接删除核销记录。

## 退款和售后

消费者可按订单类型申请未发货退款、退货退款、团购未核销退款、服务争议和其他售后。

系统保存原因、金额、凭证、责任方、处理时限和沟通记录。退款金额不得超过可退金额。优惠、积分和消费奖励按原规则撤回或分摊。

已经核销、已经部分退款或超过自动处理条件的订单进入人工审批。AI 客服可以解释规则和查询进度，不能越权同意赔偿。

## 状态要求

订单状态、支付状态、履约状态、核销状态和售后状态分开保存，不能用一个字段表示全部情况。

状态变化通过受控命令完成，并记录原状态、目标状态、操作人、原因和业务事件。非法跳转直接拒绝。

## 对账

商户能按日期、门店、渠道、支付方式和订单类型查看订单、实收、退款、优惠和净额。

支付平台账单、平台订单和商户结算记录要能核对差异。差异项显示金额、原因、负责人和处理状态。

## 验收标准

1. 前端修改价格不能改变服务端应收金额。
2. 支付回调重复十次只产生一次成功结果和一次奖励。
3. 同一核销凭证不能在两家门店重复使用。
4. 全额退款后未使用的消费奖励按规则撤回。
5. 订单各状态可以组合表达部分退款和部分履约。
6. 乐趣生活与商家小程序查看同一订单时，金额和状态一致。
7. 对账差异可追踪到原订单、支付记录和退款记录。
