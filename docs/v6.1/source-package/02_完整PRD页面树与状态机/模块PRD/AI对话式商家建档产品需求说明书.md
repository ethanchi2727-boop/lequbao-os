# AI对话式商家建档产品需求说明书

## 目标

商务人员或商家把营业执照、门头、菜单、价目表、商品照片、文件、文字和语音直接发给 Agent。Agent 自动识别、整理、检查和追问，用户不需要先面对长表单。

## 入口

- 乐趣宝 PC 端新对话；
- 乐趣宝移动端拍照、语音和文件；
- 企业微信内部应用对话；
- 一键交付项目中的“补充资料”；
- 商家小程序授权后的负责人安全入口。

所有入口调用同一套建档服务，使用同一个商户草稿和审计记录。

## 对话流程

1. 用户说明要新建或更新哪家商户。
2. Agent 检查用户是否有该商户的协助权限。
3. 用户发送照片、文件、语音或文字。
4. 系统保存原始材料并执行病毒检查、OCR、语音转写和字段提取。
5. Agent 把确定内容写入草稿，把不确定内容标记置信度。
6. 系统检查重复商户、证照、门店和联系方式。
7. Agent 每次只追问少量真正缺失或冲突的内容。
8. 用户查看一张“AI 已整理资料”卡片，确认新增、修改和公开范围。
9. 确认后写入正式商户资料，并提示受影响的小程序、GEO、AI 客服和商品。
10. 涉及发布时进入一键交付或变更发布工作流。

## 自动处理

- 识别证照主体、证照编号、地址和经营范围；
- 从门头和地图资料判断门店名称与位置候选；
- 从菜单和价目表提取商品、规格、价格和分类；
- 从语音中提取营业时间、服务范围、预约和售后规则；
- 生成商家介绍、FAQ、AI 客服知识和 GEO 公开资料草稿；
- 检查缺图、缺价、过期证照、地址冲突和公开信息风险。

## 必须确认的内容

AI 不能自行确认法律主体、支付账户、最终价格、退款规则、消费者公开联系方式、证照真实性和小程序正式发布。语音可以补充这些内容，但最后仍需可追溯的点击确认。

## 传统表单

传统表单只用于查看结构化结果、批量核对和精确纠错。页面默认先打开对话和完成进度，不把“上传资料”和“大表单”放在主导航首位。

## 异常

- 图片模糊时提示重新拍摄并展示拍摄框；
- 多家商户资料混在一起时先让用户选择归属；
- 发现同一证照已存在时停止新建并申请关联；
- AI 提取结果与历史价格冲突时不能自动覆盖；
- 企业微信文件过期或下载失败时保存失败原因并允许重新发送；
- 网络中断后从最近一次已保存材料继续。

## 验收

- 一张清晰营业执照可以自动生成主体草稿；
- 菜单照片能生成可修改的商品草稿；
- 用户能用语音完成营业时间和退款规则补充；
- 用户只需确认关键内容，不需要重复填写已识别字段；
- 每个正式字段能追溯到原材料、识别结果、确认人和时间；
- 未授权商务人员不能借对话读取其他商户资料。
