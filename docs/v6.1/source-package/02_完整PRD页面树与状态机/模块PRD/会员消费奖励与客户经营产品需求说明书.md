# 会员消费奖励与客户经营产品需求说明书

## 模块目标

商户能识别已授权的消费者，查看其咨询、订单、核销和服务记录，并按规则发放会员权益和消费奖励。系统帮助员工安排回访，不代替商户作出退款、补偿和营销决定。

## 会员身份

消费者可在乐趣生活和商家小程序中使用同一手机号关联会员。关联前取得授权，展示将合并的订单和权益范围。

一个商户的会员资料默认只在该商户范围内使用。进入跨商户平台会员前，必须另行确定授权、规则和结算，首发不自动共享。

## 消费奖励规则

每个奖励活动必须设置出资方、预算、发放条件、奖励类型、金额、有效期、使用范围、退款处理和停止条件。

系统在发放前检查订单实付、支付状态、活动预算、重复领取和风险。发放成功后写入不可重复的明细。

订单全额退款时，未使用奖励自动撤回。已使用奖励进入规则计算或人工处理。调整奖励必须填写原因并进入审计记录。

## 客户分组

首发提供新增顾客、复购顾客、长时间未到店、待售后、团购未核销和高频咨询等标准分组。

分组条件使用已授权数据。涉及敏感推断的标签不在首发提供。员工能看到分组原因，不能只看到一个无法解释的标签。

## 回访任务

商户可从分组创建回访任务，设置负责人、截止时间、建议话术和可用权益。员工完成后记录结果和下一步。

系统不能自动向个人微信联系人批量发送消息。首发可通过小程序订阅消息、站内消息或商户选择的合规通道触达，发送前检查授权和频率。

## 客户详情

客户详情显示授权摘要、最近咨询、订单、核销、售后、权益、回访和人工备注。不同角色看到不同字段。

模型生成的偏好摘要要显示来源和更新时间。员工可以更正，不能把推测当成事实。

## 风险控制

奖励活动设置单人、单日、单店和总预算上限。异常设备、集中领取、退款后反复参与和员工自发奖励进入风险检查。

客户名单导出需要权限、原因和审计。导出文件设置有效期和水印，合作伙伴不能导出消费者名单另作销售。

## 验收标准

1. 同一订单重复回调不会重复发放奖励。
2. 退款后奖励按活动规则处理，并能追溯。
3. 客户分组能说明进入原因。
4. 回访任务没有个人微信自动群发功能。
5. 模型摘要与客户事实分开保存。
6. 无导出权限的角色不能通过接口或任务下载客户名单。
