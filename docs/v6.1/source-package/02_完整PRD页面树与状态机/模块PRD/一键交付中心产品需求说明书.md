# 一键交付中心产品需求说明书

## 模块目标

一键交付中心让商务推广人员用一次发起，按标准步骤完成商户开通。系统负责自动检查和执行，商户在主体授权、名称、资质、支付和发布等关键位置确认。

一键交付不是普通插件。它是一个可暂停、可恢复、可追踪的长任务，会调用商户资料、微信开放平台、模板、AI 客服、GEO、商品、通知和验收能力。

## 发起条件

发起人必须拥有商户交付权限，且商户已创建有效合同或试点订单。

系统在发起前检查套餐、商户主体、联系人、门店、行业和服务范围。缺少必填资料时，只允许保存草稿，不能进入发布步骤。

## 标准步骤

### 创建商户

录入商户主体、品牌、门店、负责人、套餐和合同。系统检查是否已有重复主体或门店。

### 商户确认

向商户负责人发送确认页。商户确认名称、主体、门店、联系人、服务内容、数据使用和授权事项。

### 小程序授权

商户选择已有 AppID 或按指引申请。系统引导完成微信平台授权、支付账户配置和必要资质提交。

### 选择模板

根据行业推荐标准模板。商务推广人员可帮助选择模块，但商户确认名称、头像、主色、首页内容和公开资料。

### 生成预览

系统生成体验版本和二维码，自动检查缺图、空价格、无库存、无售后规则、隐私文本和不可点击按钮。

### 配置 AI 客服

从商户资料生成首批知识，导入常见问题，设置欢迎语、人工服务时间、转交负责人和禁答范围。系统运行标准问题测试。

### 完成 GEO 检查

检查公开名称、地址、电话、营业时间、类目、服务描述和网页可访问性。发现不一致时生成待办，不承诺第三方排名。

### 准备首发内容

至少上架一个可购买商品或团购。生成门店二维码、分享卡、桌贴素材和员工推广任务。

### 上传和审核

商户确认预览后，系统上传微信平台并显示审核状态。驳回时保存原因，自动提出修改建议，人工确认后重新提交。

### 发布和验收

审核通过后，由有权限人员确认发布。系统跑一遍浏览、咨询、下单、支付、核销或发货、退款和转人工测试。

### 培训和交接

商户老板与至少一名店员完成线上培训。系统记录负责人、人工接待时间、售后责任人和紧急联系人。

## 任务状态

总任务状态包括草稿、等待商户、执行中、等待外部审核、需要修改、等待发布、验收中、已完成、已暂停、已取消和失败。

每个步骤保存开始时间、结束时间、执行人、输入、输出、日志、失败原因和重试次数。

等待商户和等待微信审核不计入平台处理时长。页面分别显示平台已用时间、商户等待时间和外部等待时间。

## 人工确认点

以下动作不能自动越过：

- 商户主体和负责人确认。
- 微信平台扫码和授权。
- 小程序名称和公开资料确认。
- 支付账户和结算信息确认。
- 发布前预览确认。
- 正式发布。
- 涉及删除数据、退款或高风险规则的修改。

## 失败处理

插件调用失败时，总任务暂停在当前步骤，不重复创建商户、订单或上传记录。系统使用幂等键防止重复执行。

微信审核驳回后，页面显示原始原因、对应页面、建议修改、负责人和再次提交入口。无法自动处理的资质问题转给商户负责人。

商户长时间不处理时，系统按 24 小时、72 小时和 7 天发送提醒。超过合同规定时间可暂停交付，并记录暂停原因。

## 商务推广人员首页

首页显示自己负责商户的交付阶段、等待对象、逾期时长、下一步和风险。可以按地区、行业、套餐、负责人和状态筛选。

批量操作只能发送提醒和分配负责人。主体确认、发布和授权不能批量代替商户完成。

## 验收标准

1. 从空商户到发布完成有一条完整任务记录。
2. 任一步骤失败后可从失败位置恢复，不重复生成数据。
3. 商户能看见并完成自己的确认项，不能看见平台内部成本和其他商户。
4. 微信审核时间与平台处理时间分开统计。
5. 没有完成发布确认时，系统不能把体验版本标记为正式上线。
6. 完成状态必须同时满足小程序发布、AI 客服测试、首发内容和人员交接。
