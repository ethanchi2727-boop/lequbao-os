# 二至六级页面完整性说明

## 一、数量与范围

本包不是只有几张首页效果图。完整页面树包含 307 个二至六级节点，其中 197 个叶子页可以独立开发和验收，最深到六级。

覆盖终端：

- 乐趣宝 PC 端与移动 H5。
- 乐趣生活微信小程序。
- 商家独立小程序模板实例。

## 二、每个叶子页都有什么

` 页面树.csv ` 和 ` 页面树.json ` 中的每个叶子页都有：

- 全局唯一页面编号。
- 产品、终端、层级和父页。
- 实际路由。
- 首要角色和权限边界。
- 页面要解决的事。
- 主要组件和操作。
- 对应接口域。
- P0/P1 优先级。
- 可执行的验收条件。

## 三、八类状态是强制项

所有 197 个叶子页必须同时处理：默认、加载中、空数据、局部错误、无权限、停用、成功、可恢复失败。

简单页面不能因为“东西少”就忽略错误和无权状态。支付、退款、核销、发布、收益权、结算和插件授权还要多做幂等、确认、审计和失败恢复。

## 四、效果图和页面契约的关系

14 张 V6.1 效果图是视觉和交互真源，用来冻结全局布局、信息层级、色彩、按钮、表格、卡片、对话、Harness 右栏和移动端规则。

其余页面不能自行发明新样式。开发时用页面契约决定“页面做什么”，用效果图和设计系统决定“页面长什么样”。

## 五、开发与验收方法

1. 按 `page_id` 创建路由和页面模块。
2. 按页面契约实现主任务。
3. 接入对应接口域和权限代码。
4. 补齐八类状态。
5. 对外写操作加幂等键、二次确认、审计和恢复入口。
6. 通过该页的验收条件和对应 P0 测试后，才可标记完成。
