# 默认一键交付工作流

## 工作流编号

默认工作流编号为 `merchant_delivery_standard`。每次运行生成独立交付单，保存模板版本和规则版本。

## 第一阶段：建档

1. `merchant.create` 建立商户主体。
2. `brand.create` 建立品牌。
3. `store.create` 建立门店。
4. `staff.invite` 邀请老板和员工。
5. `profile.validate` 检查必填项和一致性。

阶段出口是资料完整率达到要求，且商户确认主体、门店和负责人。

## 第二阶段：小程序授权

1. `miniapp.choose_mode` 选择已有或新申请。
2. `miniapp.authorize` 打开官方授权页。
3. `miniapp.permission_check` 检查 AppID、类目和权限。
4. `payment.bind` 绑定商户自己的支付账户。
5. `miniapp.owner_confirm` 商户确认所有权和发布人。

阶段出口是授权有效，关键权限齐全，支付主体明确。

## 第三阶段：生成内容

1. `template.select` 选择行业模板。
2. `page.configure` 生成导航、首页和业务页面。
3. `catalog.import` 导入商品和团购。
4. `knowledge.seed` 导入标准知识。
5. `ai_service.configure` 设置 AI 店员和人工队列。
6. `geo.profile_build` 生成统一门店资料。

阶段出口是预览数据完整，没有未确认的公开内容。

## 第四阶段：体验确认

1. `miniapp.upload_preview` 上传体验版。
2. `miniapp.smoke_test` 执行自动测试。
3. `merchant.preview` 商户查看体验二维码。
4. `merchant.confirm_preview` 商户确认关键页面和规则。

自动测试失败时回到对应生成任务。商户修改关键资料时生成新配置版本。

## 第五阶段：审核发布

1. `miniapp.submit_review` 由有权人员确认提交。
2. `miniapp.review_watch` 查询审核状态。
3. `miniapp.rejection_route` 把驳回分给责任人。
4. `miniapp.release_confirm` 商户确认正式发布。
5. `miniapp.release` 执行发布。
6. `miniapp.online_check` 检查正式环境。

阶段出口是线上版本与商户确认版本一致，关键接口正常。

## 第六阶段：GEO 与经营启动

1. `geo.preview` 商户确认公开资料。
2. `geo.publish` 提交到已授权渠道。
3. `geo.evidence_collect` 保存结果和证据。
4. `launch.material_generate` 生成二维码和分享材料。
5. `launch.first_offer` 建立首个团购或商品推荐。
6. `launch.staff_task` 给员工分配推广任务。

## 第七阶段：验收

1. `acceptance.business_flow` 走通业务测试。
2. `acceptance.ai_handoff` 测试 AI 回答和人工接管。
3. `acceptance.geo` 检查资料、链接和证据。
4. `acceptance.merchant_signoff` 商户确认交付。
5. `operation.day7_task` 建立第 7 天检查。
6. `operation.day30_task` 建立第 30 天检查。

## 人工确认点

`miniapp.authorize`、`payment.bind`、`merchant.confirm_preview`、`miniapp.submit_review`、`miniapp.release_confirm`、`geo.preview` 和 `acceptance.merchant_signoff` 不能由 AI 自动跳过。
