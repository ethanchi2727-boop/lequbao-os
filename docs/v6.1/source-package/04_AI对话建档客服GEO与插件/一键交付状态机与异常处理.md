# 一键交付状态机与异常处理

## 任务结构

一个交付单包含多个任务组。任务组包含任务、前置条件、执行方式、责任人、重试规则、补偿动作和验收证据。

交付单不以一个长请求从头跑到尾。每一步完成后保存状态，服务重启或第三方超时后可以从安全位置继续。

## 任务状态

`PENDING → READY → RUNNING → WAITING_APPROVAL → SUCCEEDED`

异常状态包括 `BLOCKED`、`RETRYING`、`FAILED`、`REJECTED`、`COMPENSATING`、`ROLLED_BACK` 和 `CANCELLED`。

## 前置条件

- 没有商户主体和门店资料，不能生成正式配置。
- 没有 AppID 授权，不能上传代码。
- 没有商户预览确认，不能提交审核。
- 没有审核通过，不能正式发布。
- 没有支付主体确认，不能打开真实收款。
- 没有知识审核，AI 不得对外引用商户规则。

## 幂等与重试

每个外部调用使用交付单 ID、任务 ID 和动作版本组成幂等键。读取状态可以自动重试。上传、提交审核、发布和数据写入在重试前必须先查询实际结果。

网络错误使用退避重试。参数错误、权限不足、资质缺失和审核驳回不自动重试，直接建立责任明确的处理任务。

## 审核驳回

系统把驳回分为名称、类目、资质、隐私、内容、页面、支付、代码和其他九类。每类给出需要商户、商务、产品或研发处理的动作。

修正后生成新的配置版本或模板版本。旧的商户确认不能自动沿用到关键内容已经变化的新版本。

## 第三方未知状态

上传、审核或发布接口超时后，任务进入 `BLOCKED`，先查询第三方状态。只有确认没有执行时才能再次发起。

无法查询时，显示“结果待确认”，不得显示成功，也不得连续提交多个审核单。

## 部分成功

小程序、GEO、AI 店员和经营启动互相独立记录。GEO 某个渠道失败时，不撤销已经发布的小程序。小程序审核未过时，知识库和门店资料可以继续准备，但不能对外宣称交付完成。

## 取消

商户在正式发布前可以申请取消。系统停止未执行任务，撤销临时凭证，并保留已发生的第三方费用和审核记录。

已经正式发布后，操作称为停用或下线，不称取消。下线要检查订单、退款、核销和顾客通知。

## 回退条件

发生以下任一问题时触发回退评估：

- 无法登录或大面积白屏。
- 真实支付、退款、订单、核销出现严重错误。
- 跨商户数据泄露或权限绕过。
- AI 店员对外暴露其他商户资料。
- 发布内容与商户确认版本不一致。

回退动作、执行人、影响商户和恢复结果写入同一个交付单。
