# 一键交付总体方案

## 产品定义

“一键交付”是乐趣宝的顶层工作流，不是一个插件。

工作流负责收集资料、检查资质、调用小程序、GEO、AI 客服、知识库、团购和通知等能力，并把多个长任务排成一个可追踪的交付单。插件只负责一个明确能力，例如上传小程序代码、查询审核结果或发送企业微信通知。

商务推广人员点击一次“新建交付”，不等于系统可以跳过商户确认和微信审核。商户仍需确认小程序名称、主体、类目、支付账户、隐私内容和发布版本，也要完成扫码授权。

## 898 元套餐的默认交付结果

- 一个商户主体、一个品牌和一家门店档案。
- 一个由商户拥有 AppID 的标准独立小程序。
- 一套标准首页、商品、团购、购物车、订单、核销、会员和 AI 店员页面。
- 一套商户知识库和首批常见问题。
- 一次 GEO 基础资料整理、发布和可验证检查。
- 一个乐趣宝工作台，包含老板和两名员工账号。
- 一套首次上线二维码、分享卡和门店推广物料数据。

套餐包含订阅期内的标准小程序生成、托管、升级和维护。小程序主体、名称和 AppID 归商户。平台模板、后台服务和源代码不随订阅转让。

## 商务人员的操作

商务人员只需完成以下动作：

1. 在乐趣宝选择“新建商户交付”。
2. 邀请商户填写资料并完成授权。
3. 选择行业模板和首页组件。
4. 与商户一起确认预览版。
5. 点击“提交审核”。
6. 处理系统标出的缺件、驳回或需要商户确认的事项。
7. 发布后完成全流程测试并交付二维码。

系统负责生成页面、写入门店资料、装入标准知识、配置 AI 店员、整理 GEO 资料、上传体验版、查询审核结果和记录证据。

## 交付单状态

交付单主状态为：

`DRAFT → WAITING_MERCHANT → VALIDATING → GENERATING → PREVIEW_READY → WAITING_CONFIRMATION → UPLOADING → IN_REVIEW → READY_TO_RELEASE → RELEASING → ACCEPTANCE → ACTIVE`

任何执行状态都可以进入 `BLOCKED`、`REJECTED`、`FAILED`、`ROLLBACK_REQUIRED` 或 `CANCELLED`。系统必须显示阻塞原因、责任人、下一步和预计时间。

## 一键交付的任务组

### 商户资料

建立商户、品牌、门店、员工、类目、营业时间、售后和隐私资料。资料缺失时，其他任务不能拿默认值冒充商户事实。

### 小程序

完成 AppID 授权、模板选择、页面配置、支付配置、体验版上传、商户确认、微信审核、发布、升级和回退记录。

### AI 店员

建立标准知识库、导入商户资料、绑定商品和订单工具、设置转人工队列、配置营业时间和风险规则。

### GEO

建立统一门店资料，生成结构化内容，发布到已授权渠道，保存提交凭证，并定期检查地址、电话、营业时间和入口是否一致。

### 经营启动

生成门店二维码、商品分享卡、第一条团购、员工推广任务和上线检查清单。系统提供材料，商户负责线下摆放和实际推广。

## 自动与人工分界

资料格式检查、页面生成、知识模板导入、体验版上传、状态查询和证据归档可以自动执行。

小程序名称、主体授权、类目资质、隐私内容、支付账户、最终预览、提交审核、正式发布和回退必须由有权人员确认。审批结果要写入审计记录。

## 时间计算

平台交付时间从商户资料和授权完整后开始。微信审核、商户补件、商户确认和第三方故障时间单独记录，不计入平台自动处理时长。

工作台按平台处理中、等待商户、等待微信、等待第三方和内部异常五类展示耗时。销售不能把微信审核时间承诺成平台可控制时间。

## 验收

交付完成前必须走通“打开小程序—浏览商品—加入购物车—下单支付—查看订单—申请售后—AI 咨询—员工接管—核销或发货—查看经营报告”的测试流程。

没有支付场景的行业，需走通预约或团购核销流程。测试订单使用明确标识，并在验收后按规则退款或关闭。
