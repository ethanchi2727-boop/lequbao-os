# 插件接口与事件约定

## 统一调用头

每次插件调用必须包含：

- `request_id`：请求编号。
- `idempotency_key`：幂等键。
- `tenant_id`：商户编号。
- `store_id`：门店编号，未涉及门店时可为空。
- `actor_id`：员工、顾客或系统任务编号。
- `actor_type`：操作者类型。
- `task_id`：工作流任务编号。
- `permission_token`：短时权限令牌。
- `deadline_at`：最晚完成时间。
- `trace_id`：审计跟踪编号。

插件不能信任客户端直接传入的商户范围。服务端要用权限令牌重新解析。

## 统一结果

```json
{
  "status": "SUCCEEDED",
  "result": {},
  "error": null,
  "external_reference": "",
  "retryable": false,
  "completed_at": "2026-08-15T10:00:00+08:00"
}
```

`status` 可取 `SUCCEEDED`、`PROCESSING`、`FAILED_RETRYABLE`、`FAILED_FINAL`、`WAITING_HUMAN`、`PERMISSION_DENIED` 和 `UNKNOWN`。

## 错误要求

错误必须包含稳定错误码、给员工看的说明、给系统的分类、是否可重试和建议动作。不得把第三方密钥、完整请求或顾客敏感资料放进错误文本。

## 事件格式

```json
{
  "event_id": "evt_01",
  "event_type": "miniapp.review.approved",
  "event_version": 1,
  "tenant_id": "merchant_01",
  "store_id": "store_01",
  "subject_id": "delivery_01",
  "occurred_at": "2026-08-15T10:00:00+08:00",
  "producer": "miniapp_delivery",
  "data": {}
}
```

事件消费者要按 `event_id` 去重。事件版本增加时保持旧字段含义不变。

## 回调安全

第三方回调必须验证签名、时间和重复事件。验证失败直接拒绝。回调处理先入队，再快速响应第三方。业务处理失败由内部任务重试。

## 网络和密钥

插件只能访问清单声明的域名。生产密钥使用密钥管理服务，按商户或平台授权范围隔离。密钥轮换不需要重新发布插件代码。
