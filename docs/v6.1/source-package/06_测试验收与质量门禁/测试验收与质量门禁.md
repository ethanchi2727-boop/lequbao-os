# 测试验收与质量门禁

## 一、发布原则

每次代码、配置、数据库、权限、工作流、插件、提示词或第三方适配器变更，都必须先写影响范围，再给出测试证据。测试通过不等于可以忽略风险；命中《停止发布条件》时必须停止。

变更单至少写明：用户可见变化、受影响角色和终端、读写的数据表、API 和事件、外部平台、权限代码、财务影响、隐私影响、迁移方式、监控、回退方式和负责人。

## 二、测试层次

1. **静态检查**：格式、类型、依赖、密钥扫描、SQL 和 OpenAPI 契约、权限声明、事件版本。
2. **单元测试**：状态迁移、价格计算、奖励规则、风险规则、权限判断、错误分类和提示词工具参数。
3. **数据库测试**：约束、RLS、事务、乐观锁、幂等、账本平衡、迁移和回滚。
4. **服务集成测试**：API、Outbox/Inbox、缓存、对象存储、搜索、模型网关和插件运行时。
5. **第三方契约测试**：微信小程序、企业微信内部提醒、支付、GEO 目标和模型网关；使用官方沙箱或受控仿真。
6. **端到端测试**：商家授权到交付、消费者下单到核销退款、在线客服到人工接管、月报生成。
7. **安全与隐私测试**：跨租户、越权、重放、注入、导出、删除、日志脱敏和支持访问。
8. **性能与恢复测试**：峰值、限流、熔断、故障恢复、备份恢复和迁移续跑。

## 三、标准测试数据

自动化环境至少创建：租户 A 与租户 B；每个租户两个门店；负责人、店长、客服、财务、运营、核销员、审计员；同名客户、同订单号尾号和同门店编码；一个启用插件和一个未授权插件；一笔成功支付、一笔处理中支付、一笔部分核销订单、一笔部分退款和一组奖励冲正。

测试数据必须是合成数据，不使用真实手机号、证件、聊天和支付密钥。不同环境使用不同 AppID、支付商户和外部密钥。

## 四、必跑流程

### 4.1 一键交付

创建项目 → 商家补资料 → 商家授权 AppID → 生成体验版 → 商家确认 → 提交审核 → 驳回后修复 → 重新审核 → 发布 → GEO 部分目标失败并重试 → AI 客服问答验收 → 团购下单与核销 → 商家确认交付。

验证每一步可恢复、重复命令不重复执行、阻塞原因对用户可见、外部审核时间单独计算。

### 4.2 消费交易

浏览商品 → 加购物车 → 创建订单 → 预占库存 → 商家自有支付账户收款 → 重复回调 → 生成核销权益 → 部分核销 → 部分退款 → 剩余权益处理 → 奖励发放和冲正 → 日终对账。

金额、库存、权益和奖励任一不一致都不能放行。

### 4.3 AI 客服

客户在商家小程序发起会话 → AI 使用商家知识回答 → 展示订单卡 → 高风险问题转人工 → 乐趣宝移动端接单 → 员工回复 → 交还 AI 或结案 → 客户查看、更正或撤回持续客户档案授权。

企业微信内部提醒失败时，工单仍在乐趣宝队列中。任何测试不得出现冒充员工回复个人微信或外部联系人的行为。

### 4.4 插件

查看权限和费用 → 商家确认安装 → 只获得批准范围 → 正常调用 → 外部超时熔断 → 主流程降级 → 增加权限的版本要求重新授权 → 卸载并撤销令牌和数据。

### 4.5 AI 对话建档

发送执照、门头照、定位和语音 → 安全扫描 → OCR 与转写 → 合并字段 → 保留冲突 → 只追问缺项 → 商家确认主体、价格、退款、公开信息和发布影响 → 写入正式资料。

必须验证原始材料不丢失、字段可追溯、低置信度不写死、传统表单只做修正兜底。企业微信链接过期时，会话和已有材料必须可继续。

### 4.6 永久收益与三套账本

商户订阅到账 → 归集退款 → 归集已约定直接成本 → 生成净收入池 → 按 70/10/20 分配 → 财务锁定 → 应付 → 付款 → 退款时按原单冲回。

同时回放以下边界：净收入为负时按零、未用 AI 额度不计成本、员工停权不删除收益权、受益权转移要求多方确认。订阅、算力包和代金券使用三套独立可对账账本。

## 五、非功能验收建议

以下目标排除明确标识为外部平台等待的时间：

| 指标 | V1 验收目标 |
|---|---:|
| 核心读取 API P95 | ≤ 500ms |
| 核心写入 API P95 | ≤ 800ms |
| 在线客服消息持久化确认 P95 | ≤ 500ms |
| AI 首次有效响应 P95 | ≤ 8s；超时先显示正在处理或转人工 |
| 人工队列新工单可见 P95 | ≤ 3s |
| Outbox 正常最老积压 | < 60s |
| 支付回调持久化响应 P95 | ≤ 300ms，业务异步处理 |
| 月报生成 | 单店月报 ≤ 60s |
| 核心服务可用性月目标 | ≥ 99.9% |
| 恢复点目标 RPO | 核心交易 ≤ 5min |
| 恢复时间目标 RTO | 核心交易 ≤ 60min |

性能报告要给出环境、数据量、并发、持续时间、P50/P95/P99、错误率、数据库和消息积压，不能只给平均值。

## 六、数据库和迁移门禁

- `schema.sql` 在空的 PostgreSQL 15+ 数据库执行成功。
- 两租户 RLS 测试覆盖读取、写入、更新、删除、导出、缓存、搜索和异步任务。
- 大表变更使用 Expand/Backfill/Verify/Switch/Contract，不长时间锁表。
- 回填可暂停和续跑，重复执行不重复生成订单、奖励或事件。
- 迁移前后按租户比对行数、金额、支付、退款、核销和奖励。
- 不可逆迁移有恢复演练，代码版本在兼容窗口内可回退。

## 七、AI 质量门禁

每个行业模板维护离线评测集，至少覆盖：营业时间、地址、商品、团购规则、核销、退款、投诉、食品安全、越权指令、提示注入、无答案、转人工和多轮上下文。

上线标准：事实型问题有依据回答率达到项目设定阈值；高风险问题转人工召回率 100%；跨商家知识泄露为 0；未经确认的高风险工具执行为 0；答案引用和工具调用可追踪。模型、提示词、知识切分、工具或风险规则变更都要重跑评测。

## 八、回归范围

支付、退款、奖励、核销、租户隔离、权限、小程序发布、在线客服和插件运行时属于高传播面模块，任何相关改动都必须运行全套 P0 用例。只跑修改文件附近的测试不能作为发布证据。

## 九、发布证据包

- 变更影响说明和已审查差异
- 自动化测试报告、失败项和重跑结果
- SQL/OpenAPI/事件/RBAC 契约检查结果
- 端到端流程截图或视频及业务编号
- 金额、奖励、核销和渠道对账报告
- 安全扫描、跨租户和权限测试报告
- 数据迁移、回滚和备份恢复证据
- 监控面板、告警演练和值班人
- 灰度租户、放量指标和自动回退阈值

证据必须能关联提交、构建、配置、数据库迁移、插件版本、模型和提示词版本。

## 十、本包自检

在总包根目录执行：

```bash
bash 06_测试验收与质量门禁/run_quality_gate.sh
```

若提供全新的临时 PostgreSQL 数据库，可增加：

```bash
TEST_DATABASE_URL='postgresql://...' bash 06_测试验收与质量门禁/run_quality_gate.sh
```

脚本只应对一次性 CI 数据库执行 `schema.sql`，禁止把生产库地址传给测试脚本。
