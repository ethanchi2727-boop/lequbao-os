# 停止发布条件

命中以下任何一项，立即停止发布或继续放量。负责人不能以“先上线再观察”口头豁免；解除必须有修复、复测和书面批准。

## 一、绝对停止项

1. 任意跨租户读取、写入、缓存、搜索、向量召回、对象下载、事件或日志泄露。
2. 未授权角色可以退款、核销、发布小程序、改奖励、结算、导出客户、安装插件或提权。
3. 重复请求或重复回调会造成重复扣款、退款、库存扣减、核销、奖励、结算或发布。
4. 账本任一交易借贷不平，或订单、渠道支付、退款、奖励、核销对账存在未解释差异。
5. 消费者资金进入非商家约定支付账户，或平台无法说明资金与手续费去向。
6. 高风险 AI 问题可绕过人工处理，或模型可直接执行未经确认的退款、赔付、发布、导出、批量触达和权限变更。
7. 客户聊天或知识能被另一商家检索，或模型、日志、事件中出现不应暴露的证件、密钥、完整手机号和支付信息。
8. 小程序线上发布的构建物与商家确认或审核通过的版本不一致，且不能安全回退。
9. 第三方回调未验签，或外部事件重放能改变业务结果。
10. 插件可越过批准权限、访问其他租户、访问未声明外部域名或读取平台主密钥。
11. 数据库迁移不可续跑、无法验证金额、破坏旧版本兼容，或未做不可逆操作的恢复演练。
12. 审计日志无法写入、可被普通应用角色修改，或高风险操作没有真实操作者。
13. 存在未处理的已知严重或高危安全漏洞，或生产密钥进入代码、镜像、日志和前端包。
14. P0 自动化用例失败、被跳过、仅靠人工口头确认或结果不能关联本次构建。
15. 订阅净收入池没有按商务 70%、尚智 10%、乐趣生活 20% 分配，或分配合计不等于净收入池。
16. 未用 AI 额度、通用研发、行政、品牌、办公或不可追溯成本被放到分配前扣除。
17. 商务人员账号停用、离岗或权限收回时，系统自动删除其已确权的商户永久收益权。
18. 已付款结算单被原地改写，或退款没有按原订单、原政策和原受益人生成冲回分录。
19. 算力包未按是否存在有效区县服务商使用 50/30/20 或 50/30/10/10 政策快照，或代金券重新启用旧的多公司 15/15/70 拆分。

## 二、条件停止项

以下项目超过阈值且没有已验证降级方案时停止放量：

| 指标 | 停止阈值 |
|---|---:|
| 核心 API 5xx | 连续 5 分钟 > 1% |
| 支付回调处理失败 | 连续 5 分钟 > 0.5% 或出现重复业务结果 |
| Outbox 最老积压 | > 10 分钟 |
| 死信新增 | 核心交易事件任意新增，且原因未知 |
| 在线客服消息持久化失败 | 连续 5 分钟 > 0.5% |
| 人工工单丢失 | 任意一例 |
| 小程序发布失败 | 灰度租户 > 5%，且不是明确的商家资质原因 |
| 插件超时 | 核心页面受影响或连续 10 分钟 > 5% |
| 数据库连接或锁等待 | 达到容量红线或影响核心写入 |
| 监控盲区 | 核心指标、告警或值班联系人不可用 |

## 三、立即回退或关闭开关

- 资金、租户、权限、隐私或数据损坏问题：停止相关写入，必要时回退整个版本。
- 单一插件或 GEO 目标问题：熔断该插件或目标，保留主流程。
- 新模型或提示词问题：切回上一评测通过版本，人工队列继续工作。
- 小程序新版本问题：停止继续发布，按版本记录回退到上一稳定构建。
- 报表或埋点问题：关闭非关键消费者，不能阻塞订单、客服和支付。

## 四、解除停止的证据

必须提供根因、影响租户和数据范围、修复差异、定向复测、全套 P0 回归、数据修复或对账结果、监控恢复、回退验证和批准人。涉及客户或资金影响时，还需给出通知、补救和财务确认。

## 五、灰度发布顺序

内部测试租户 → 2 至 3 家友好商家 → 单行业 10% → 单行业 50% → 全部试点。每一阶段观察完整高峰周期；自动回退阈值预先配置，不能上线后临时决定。
