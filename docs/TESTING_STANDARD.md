# 项目测试规范

本规范适用于任何使用本模板创建的项目。所有 AI 开发和人工开发都必须遵守。

## 1. 测试目标和完成定义

### 1.1 测试目标
- 确保所有功能按设计文档和需求正确实现
- 发现并修复代码缺陷和业务逻辑错误
- 保证系统稳定性、安全性和性能
- 验证接口正确性和数据一致性
- 确保支付、退款、结算等资金相关功能准确无误

### 1.2 完成定义
- 所有新增/修改功能的测试用例 100% 覆盖
- 所有 P0 级测试用例通过
- lint 检查通过（无错误，警告不超过 5 个）
- 类型检查通过
- 单元测试覆盖率不低于 80%
- 接口测试通过率 100%
- 关键端到端测试通过
- 构建成功

## 2. 测试分层

### 2.1 单元测试
- **范围**：单个函数、方法、组件的独立测试
- **工具**：Jest / Vitest（根据项目技术栈选择）
- **要求**：覆盖正常路径、边界条件、异常情况
- **隔离**：使用 Mock 隔离外部依赖（数据库、API、第三方服务）

### 2.2 接口与数据库集成测试
- **范围**：API 接口、数据库操作、事务处理
- **工具**：Supertest / Axios + Jest/Vitest
- **要求**：验证接口请求/响应格式、数据一致性、事务正确性
- **环境**：使用测试数据库，测试前后清理数据

### 2.3 端到端测试
- **范围**：用户完整操作流程
- **工具**：Playwright / Cypress
- **要求**：覆盖核心业务流程，模拟真实用户操作
- **环境**：测试环境，不使用正式数据

## 3. 测试方法

### 3.1 正常场景测试
验证功能在标准输入和正常流程下的正确性。

### 3.2 边界条件测试
- 最小值、最大值、空值、空字符串
- 长度边界、数量边界
- 时间边界（过期、即将过期）

### 3.3 异常场景测试
- 参数错误、格式错误、类型错误
- 权限不足、未登录状态
- 网络异常、超时
- 数据库异常、事务回滚

### 3.4 重复执行测试
- 相同请求重复提交
- 相同操作重复执行
- 验证幂等性

### 3.5 并发测试
- 多个用户同时操作同一资源
- 并发领取、并发下单、并发结算
- 验证数据一致性和锁机制

### 3.6 幂等性测试
- 相同请求多次到达，结果一致
- 支付/回调重复到达不重复处理

### 3.7 权限测试
- 不同角色访问权限验证
- 越权访问阻止
- 登录状态验证

### 3.8 状态转换测试
- 业务对象状态流转正确性
- 非法状态转换阻止

## 4. 测试数据规则

### 4.1 测试数据
- 使用测试专用数据，不得使用真实用户数据
- 测试数据应覆盖正常、边界、异常场景
- 测试数据应可重复生成和清理

### 4.2 测试账号
- 创建测试专用账号（覆盖项目所有角色）
- 测试账号与正式账号严格隔离

### 4.3 测试数据库
- 使用独立的测试数据库
- 测试前清理数据，测试后可选清理
- 禁止连接正式数据库

### 4.4 Mock 规则
- 外部 API 必须 Mock（支付、短信、推送等）
- 随机数、时间相关函数建议 Mock 以保证测试稳定性
- Mock 数据应与真实返回格式一致

### 4.5 数据清理
- 单元测试：每次测试后清理
- 集成测试：测试套件前后清理
- 端到端测试：关键数据清理

## 5. 禁止事项

### 5.1 禁止使用正式环境
- 禁止使用正式支付接口
- 禁止连接正式数据库
- 禁止使用真实用户数据
- 禁止使用正式短信/推送服务

### 5.2 禁止破坏测试完整性
- Bug 修复必须留下永久回归测试
- 测试失败不得通过删除测试解决
- 测试失败不得通过跳过测试解决
- 测试失败不得通过降低断言标准解决
- 禁止用 `--if-present` 让缺失的测试命令静默通过
- 禁止把"没有测试"显示为"测试通过"

## 7. 未执行检查的报告规则

- 未执行的检查必须标注"未执行"
- 不得描述为"通过"或省略
- 说明未执行的原因
- 评估未执行带来的风险

## 8. 自动化测试规范

### 8.1 命名规范
- 单元测试：`[模块]-[功能].spec.ts`
- 接口测试：`[模块]-[接口].test.ts`
- 端到端测试：`[场景]-[流程].e2e.ts`

### 8.2 目录结构
```
tests/
├── unit/           # 单元测试
│   ├── services/   # 服务层测试
│   ├── utils/      # 工具函数测试
│   └── components/ # 组件测试
├── api/            # 接口测试
└── e2e/            # 端到端测试
```

### 8.3 维护规范
- 测试用例应与代码同步更新
- 删除功能时同步删除相关测试
- 新增功能时同步新增测试
- 定期清理不稳定测试

## 9. 测试不稳定处理

### 9.1 超时处理
- 设置合理超时时间
- 避免固定等待，使用条件等待

### 9.2 重试机制
- 偶发失败可设置重试（最多 3 次）
- 标记为不稳定测试
- 分析根因并修复

### 9.3 固定等待原则
- 禁止使用固定等待掩盖问题
- 必须使用条件等待或事件监听

## 10. 金额测试要求

### 10.1 单位规范
- 使用整数最小货币单位（分）
- 或使用可靠高精度类型（decimal.js / big.js）
- 禁止使用浮点数进行金额计算

### 10.2 精度验证
- 计算结果精度验证
- 四舍五入规则验证
- 金额一致性验证

## 11. 风险等级

### 11.1 P0（发布阻断）
- 认证、登录、权限
- 支付、退款、结算
- 资金相关业务规则
- 数据一致性、幂等性
- 核心业务主流程

### 11.2 P1（高优先级）
- 重要功能流程
- 接口正确性
- 边界条件处理

### 11.3 P2（中优先级）
- UI 交互细节
- 非核心功能
- 性能优化

## 12. 发布阻断条件

以下任一条件不满足时禁止发布：
1. P0 测试用例未全部通过
2. 类型检查失败
3. 构建失败
4. lint 存在错误（errors）
5. 存在未解决的安全漏洞（高危）
6. 核心业务流程端到端测试未通过

## 13. 通用高风险测试用例模板

以下为大多数项目都应覆盖的高风险场景，新项目初始化时由 TRAE 根据真实业务补充具体数据：

### 13.1 支付与资金
- 支付流程正确性
- 支付回调幂等性（重复回调不重复处理）
- 全额退款
- 部分退款
- 退款冲回（佣金、权益、已结算金额）

### 13.2 余额与账户
- 余额扣减正确性
- 余额并发操作一致性
- 账户隔离

### 13.3 佣金与结算
- 佣金计算正确性
- 结算金额对账
- 分账比例正确性

### 13.4 权限
- 不同角色访问权限
- 越权访问阻止
- 登录状态验证

### 13.5 并发与幂等
- 并发领取/下单（防超卖）
- 重复请求幂等性
- 定时任务幂等性（重复执行不重复处理）
