# 乐趣生活 V6.3 唯一 UI 基线

## 一、正式锁定

本文件是乐趣生活唯一正式 UI 基线，自 2026 年 8 月 25 日起生效。V6.2 及更早视觉资料只保留为历史记录，不得继续作为新页面设计依据。

乐趣生活与乐趣宝共享品牌关系和业务能力，但不共享视觉 CSS：

- 乐趣生活：鲜活、丰富、可信、适合中国日常消费场景；
- 乐趣宝：专业、克制、清晰的 AI 工作中台；
- 两套产品必须使用独立 Theme Namespace，禁止相互复制页面级样式。

## 二、正式视觉方向

- 以生活绿建立品牌识别，以珊瑚红表达价格和抢购，以明黄表达优惠权益，以湖蓝表达活动氛围；
- 商品图片、Banner 和金刚位分类图标采用真实、饱满、可识别的商品与生活素材；
- 首页必须具备搜索、实物金刚位、优惠券、活动会场、限时抢购、生活频道和连续商品货架；
- 商品卡必须清楚呈现实物图、商品名、到手价、原价、优惠利益点和快速加购入口；
- 页面信息密度可以高，但必须通过白色分区、统一圆角、统一间距和明确标题层级保持清爽；
- 不允许用大面积空白、抽象占位图、线性文字入口或低信息密度卡片替代正式零售内容。

参考截图仅用于理解中国零售小程序的信息密度、商品表达和促销节奏，不得复制第三方品牌、页面、文案或图片素材。本包内三套核心零售素材为原创视觉资产。

## 三、五个底部 Tab

顺序和名称固定为：

1. 首页；
2. 商城；
3. 生活圈；
4. 购物车；
5. 我的。

每个 Tab 必须使用图片图标，并同时提供默认态和激活态；不允许只显示文字。激活态使用品牌色和轻量底板，默认态保持清晰但降低视觉权重。

AI 小满是跨页面悬浮助手，不占用第五或中央 Tab，不得改变五栏业务结构。

## 四、微信小程序顶部规范

- 所有一级页面必须读取微信小程序胶囊位置与安全区信息，右上角不得放置会被胶囊遮挡的按钮、文字或图片；
- 原型中的胶囊仅用于展示占位，生产代码使用微信运行时返回的真实胶囊尺寸与坐标；
- 城市入口、搜索框和胶囊位于同一顶部操作区，搜索框优先展示，不再放到 Banner 或金刚位下方；
- Banner 数据必须提供 `themeColor` 或等价主题字段，顶部通过 `--tone-top`、`--tone-mid`、`--tone-soft` 三档 Token 联动；
- 渐变从状态栏开始，吸收当前 Banner 主色，经过 Banner 和金刚位后自然过渡到页面底色；
- 切换 Banner 时只更新主题 Token，不允许页面组件自行计算或写死另一套渐变；
- 顶部必须适配状态栏高度、不同机型安全区和胶囊尺寸，禁止仅按效果图固定绝对坐标。

## 五、开发约束

- 页面必须使用乐趣生活统一 Theme Tokens、Shared Layout 和 Shared Components；
- 页面代码不得散落新增 Hex、RGB、渐变、阴影和圆角值；
- 搜索栏、金刚位、优惠券、活动会场、商品卡、价格标签、加购按钮、底部导航和弹窗必须复用共享组件；
- 新页面不得自行创造另一套主色、卡片、按钮、图标或促销表达；
- PC 管理端或乐趣宝的深色科技视觉不得进入乐趣生活消费者端；
- 原型中的演示商品和价格只用于视觉表达，生产环境必须绑定真实数据与规则。

未使用 Shared Layout、Theme Tokens 和 Shared Components 的新增页面，不允许通过 PR。

## 六、业务冻结边界

本次属于 P2 视觉升级，严禁修改以下生产逻辑：

- 用户、商家、商品和订单主数据；
- 支付、退款、拒付与退款冲正；
- 代金券模式、抽佣基数和规则版本；
- 消费者奖励、商家奖励、加速池及负额度；
- 套餐收益、算力包、佣金、分润和结算；
- 角色、权限、审计、历史流水和历史订单快照。

如视觉接入需要变更任何接口、字段、状态机或计算逻辑，必须另立需求、单独评审，不得混入本升级包。

## 七、正式验收

- 五栏名称、顺序、图标默认态和激活态全部正确；
- 顶部安全区、微信胶囊、城市入口和搜索框无重叠；
- 首页、商城、生活圈可根据 Banner 主题呈现不同顶部渐变，并在金刚位底部完成过渡；
- 首页、商城、生活圈、购物车、我的均可独立渲染；
- 商品、分类、Banner、优惠券、活动与价格层级完整；
- 中文字体覆盖、图片尺寸和非空检查通过；
- 不出现旧三公司 15%/15%/70% 分配口径；
- 不因视觉升级改变任何交易与收益结果；
- 所有新页面均继承本基线。
