# 前端产品化重建 50 阶段计划

## 目标与边界

本计划修正“API 已连接即页面已完成”的错误判定，并按 ADR-0012 修订终端拓扑。现有 PostgreSQL、API、权限、交易、支付、退款、审计和 Worker 能力继续作为业务底座；乐趣生活由同一 UniApp 工程输出 H5 与微信小程序，乐趣宝以 PC 为核心并同时提供移动 H5 与微信小程序，商家独立小程序模板保持独立。

本轮在完整本地质量门通过前不提交、不推送 GitHub；质量门通过后按用户明确指示提交并推送开发候选。每个阶段必须完成自己的自检，并把证据写回本文件或关联报告。浏览器、微信、支付、企业微信和生产凭据等真实外部验收不能用 Mock 代替。

## 页面完成定义

页面只有同时满足以下五层才可称为“产品完成”：

1. `contracted`：页面编号、角色、状态、接口域和验收用例可追踪；
2. `connected`：读取与写入使用权威 API，生产环境失效关闭；
3. `designed`：按原始效果图和设计系统实现，不使用通用信息卡冒充专属页面；
4. `interactive`：主任务、加载、空、错误、无权限、停用、成功和可恢复失败均可操作；
5. `accepted`：桌面/移动浏览器或微信真机完成视觉、触控、可访问性和关键闭环验收。

`connected` 不能替代后三层。当前 197 个叶子页的“authoritative”统计只对应前两层。

## 当前事实

- 当前线上是 `development-mock-preview`，不能接真实用户、商户或资金。
- 乐趣生活已建立 `apps/life-uniapp` 共享源码，38 个叶子任务均已迁入页面清单；旧 WXML 和临时 ESM 只保留为迁移参照。
- 乐趣宝已建立 `apps/bao-uniapp` 并通过移动 H5、微信双构建；当前是五入口业务首版，真实员工权限与任务闭环仍需逐页接入。`apps/merchant-miniapp` 是商家店铺模板，不能计入乐趣宝小程序。
- 生产 Web 镜像已改为同时封装乐趣宝 PC、乐趣生活 H5 和乐趣宝移动 H5，分别使用 `/bao/`、`/life/` 与 `/bao-mobile/`；容器级 smoke 仍需在 Docker 可用环境复验。
- 乐趣宝 135 个叶子页中，除建档流程外大部分仍由通用页面渲染器承载，视觉和交互未达到原始设计。
- 本地 H5 浏览器现已复验 PAGE-216/227/231/240 的 1024×768 与 390×844 路由、无溢出、无控制台告警和未登录恢复入口；真实会话、微信真机和 provider 验收仍保持待办。
- 乐趣生活当前有 38 个独立叶子页；加上 5 个既有工作台叶子，共 43 个跨产品叶子被矩阵标记为 `designed`/`interactive`。5 个商户会话页明确安全关闭，不冒充已连接；全部页面仍保持 `accepted: false`，等待真实会话、微信真机和受控环境证据。
