# 乐趣生活正式路由功能回退修复

## 范围

基于 `ea885916a48a2bd380f0bfcb79507e66bb2312dc`，恢复 PAGE-201、203、204、209、213 的真实发现、搜索、商品与团购页面，以及 PAGE-218、221、224、228、229、231、232、235、237、239、242、248、250、254、255、258、259、262、264 的权威业务组件入口。修复前，部分页面显示固定价格、商户、个人信息、概念文案或无效路由，且原有业务组件只被导入而未渲染。移除 `LifeJourneyPage.vue` 中误混入的非 CSS 文本。

## 契约与数据

- 影响用户：乐趣生活 H5 和微信小程序消费者。
- 页面和 API：上述页面恢复调用现有 `LifeJourneyPage`、`LifeServicePage`、`LifeSurface` 与 `lifeSession`，继续使用原有发现、购物车、核价、支付意图、订单、售后、授权和客服接口。
- 数据表、事件、权限、资金规则和历史数据：无变更。客户端不把固定演示金额、授权状态或支付结果呈现为真实业务事实。
- 防回退：`frontend:check` 检查 38 个正式乐趣生活路由的概念稿及无效入口，并核对受影响页面确实渲染对应业务组件或数据页面。

## 验证与发布

先运行乐趣生活测试、结构检查、前端矩阵检查、300 项路由检查与 H5/微信双构建；再在有真实测试身份和 PostgreSQL 的环境验收搜索、商品、结算、授权与客服正常态及失败态。正式支付、微信真机、外部供应商和受控发布证据仍按现有发布门禁执行。发布时仅替换对应前端产物，回滚到上一个已验证的前端产物；没有数据库回滚或财务重算。财务对账以服务端原有订单、支付、退款和奖励台账为准。

## 同批本地门禁修复

- 远程基线有 70 个文件未符合仓库 Prettier 规则；执行统一格式化，未更改业务判断。修复格式化暴露的脆弱源码字符串断言，并让报价拒绝测试使用未来有效期，确保实际进入价格校验分支。
- 数据库权威 schema 已到 `0028`、165 张表，但开发容器与预览增量迁移停在 `0027`；补齐 `0028` 应用步骤，并同步部署、受控证据与性能快照的版本/表数契约。此处只验证了脚本和静态契约，尚未在 PostgreSQL 中实际执行迁移。
- 首次远程 PostgreSQL 初始化指出 `0028` 的复合外键缺少被引用列的唯一约束；在创建抵扣投影表前为 `reward_grants(tenant_id,id)` 增加唯一约束。该约束不改变原有主键或历史金额事实；远程 `postgres-contract` 已验证 clean schema。
- 全仓测试先构建其所需的 contracts、Harness adapter 和工具网关；工作台测试使用根工作区锁定的 Vitest；重新生成锁文件与 SBOM，使依赖安装和供应链校验使用同一份清单。
- 首次远程依赖审计发现传递依赖 `fast-uri` 与 `adm-zip` 的高危公告；将 `fast-uri` 3.x/4.x 分别锁到 3.1.6/4.1.3，`adm-zip` 锁到 0.6.1。重新安装、生成 SBOM 后，本地 `pnpm audit --prod --audit-level high` 通过（剩余 2 项低危、5 项中危）。
- 第二次远程门禁确认 PostgreSQL 契约与代码质量通过；容器镜像和两个开发栈因未先构建 Harness adapter/工具网关而无法解析 API 的工作区导入。把三个共享运行时包的构建放在容器通用源码阶段，并同步开发容器初始化脚本。第三次远程容器和两个开发栈通过。
- 首页存在永远不渲染的图片区块与仅为测试保留的图片导入，导致 H5 超出 8 MiB。移除虚假运行时引用，保留官方图片原件与哈希校验，修正测试检查真实页面和组件。H5 产物为 7,561,233 字节，低于 8,388,608 字节上限。
