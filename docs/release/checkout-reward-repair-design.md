# 奖励抵扣资金闭环修复设计（待业务/财务确认）

本文件把 `checkout-reward-financial-gap.md` 的 P0 缺口转成可审阅的实现顺序。以下金额、记账和退款方案均为**建议**，尚未成为获批资金规则；确认前不修改生产资金逻辑，不合并或发布草稿 PR。

## 必须先确认的四项决定

| 决定     | 建议口径                                                                                                                                   | 必须补充的业务规则                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 应付结构 | 保留商品原价、促销优惠、运费、旧奖励抵扣和渠道现金实付五个独立金额；`现金实付 = 商品原价 + 运费 - 促销优惠 - 旧奖励抵扣`，各金额按分记账。 | 旧奖励是否允许抵运费、各商户/商品使用范围及抽佣基数。                     |
| 使用时点 | 报价只预留，成单保持占用；经渠道验签确认成功后才写 `REWARD_REDEEM` 双分录并增加奖励已使用投影。失败、超时、取消释放占用。                  | 零现金实付订单是否允许，以及它的独立确认、履约和审计主体。                |
| 退款     | 渠道现金退款只处理原渠道实收；旧奖励抵扣的返还或冲正使用原订单和活动规则快照，新增不可变反向分录。                                         | 全额/部分退款的分摊、过期和再次使用奖励如何处理；无法自动判定时由谁审批。 |
| 存量     | 保留 `0028–0030` 历史订单、抵扣与账本原值；先用受控备份和渠道对账分类，再审批任何补偿或冲正。                                              | 已 `SETTLED` 记录的差异处理主体、冻结边界和审核凭证。                     |

## 拟议实施顺序

1. **冻结事实并盘点。** 在授权的隔离备份上执行只读 `database/preflight/checkout-reward-financial-exposure.sql`，按商户、订单、渠道交易和账本在受控环境内复核差异。汇总结果可进验收材料；身份、订单和交易明细留在受控环境。没有真实备份和渠道回执时，不推断实际损失。
2. **扩展数据契约。** 新迁移版本增加独立的订单奖励抵扣金额及不可变规则版本，调整订单金额恒等式和商业快照不可变触发器；既有订单默认抵扣为零，历史 `SETTLED` 投影保留原语义。新投影显式标记规则版本，避免把旧的 `SETTLED` 当作已收到渠道资金。新约束及索引只对新记录建立受控状态路径；旧记录冲突先调查，不自动重写。
3. **原子成单与并发预留。** 对同一奖励资格加行锁，计算未过期且仍有效的其他占用；同一商户组内将订单、库存预留、抵扣占用与幂等回执放在一个数据库事务内提交或回滚。当前 `createGroupOrder` 和奖励扣减使用两个事务，必须消除“订单已创建而抵扣失败”的中间态。跨商户组仍逐组独立记账并明确部分成功回执。
4. **渠道成功/失败。** 支付意图只使用渠道现金实付额；成功回调验签、金额和商户账户匹配后，在同一事务里写订单状态、`REWARD_REDEEM` 双分录、奖励投影及 Outbox。重复回调只返回已确认事实。失败、过期和取消只释放未记账的抵扣占用与库存，并保留状态历史；不删除已产生的资金事实。
5. **退款和零现金。** 按已确认的规则版本实现现金退款与旧奖励返还的独立处理，处理部分退款的逐项分摊和重复回调；零现金订单不得伪造渠道交易号或支付成功回调。过期、再次使用及历史差异走有审批的人工异常单或明确的规则分支。
6. **终端与对账。** 结算、支付、订单详情、退款和奖励流水分别展示原价、优惠、旧奖励、渠道实付及最终服务端状态。按商户/日/订单核对现金实付、渠道交易、现金退款、奖励使用、奖励返还和双分录余额；不得把测试网关响应作为真实资金验收。

## 可执行门禁

| 层级            | 必须证明                                                                                                                                |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 合约与单元      | 负金额/超额抵扣拒绝、金额恒等式、原规则版本快照、同幂等键重放、跨账号/租户隔离、零现金边界。                                            |
| PostgreSQL 集成 | 并发报价和成单不会超用同一奖励；订单、库存、占用同事务；成功/失败/重复支付回调后账本与投影一致；全额/部分退款与重复回调保持双分录平衡。 |
| 旧库迁移        | 从真实备份试迁移，核对表/版本、旧订单与奖励总额不变、锁等待、恢复时长、RLS、差异清单和回滚预案。                                        |
| 受控端到端      | 用获批商户支付账户和供应商沙箱走真实回调及对账文件；浏览器、微信真机覆盖报价、支付、失败、退款、奖励流水和跨账号拒绝。                  |
