# Controlled-suite execution readiness

Date: 2026-08-19

This is an execution audit, not a PASS manifest. The exact candidate commit, controlled environment, immutable artifacts and independent reviewer are still required by `pnpm launch:gate`.

The 300-stage continuation now has an executable mapping in `docs/release/controlled-300-stage-map.json`. `pnpm controlled:stage-map` verifies that stages 281–291 preserve the exact controlled-plan suite order and all 47 declared artifacts, while stages 292–300 preserve the frozen release-control codes and commands for candidate binding, non-overwriting capture, independent decisions, result assembly, exact packaging, immutable draft publication, protected verification, independent attestation and the final launch decision. The verifier also rejects reordered stages, suite/control kinds outside their frozen ranges, duplicate or blank completion evidence, non-integer artifact counts and any stage-level execution, approval or completion claim. The map intentionally contains no PASS or DONE field. On 2026-08-23, names-only inventory still reported 57 unique requirements and controlled preflight reported 0 configured, so none of stages 281–300 is claimed complete.

Assembly and launch verification inspect the evidence bytes as well as their hashes. Empty, binary, malformed or empty JSON, placeholder-only verdicts and common unredacted credential forms fail closed; this minimum content/redaction gate does not replace the technical review required for each suite.

The 39 JSON slots additionally have exact minimum semantic contracts shared by capture, assembly and launch verification. Generated checklists name every required field/type, candidate/deployment binding, operational range, digest/date format and PASS, true or empty-unresolved invariant; structurally valid but unrelated or differently bound JSON is rejected.

Assembly and launch verification additionally reconcile seven multi-artifact suites: commerce quantities, payment account/amount identity, backup/restore identity, performance image topology, WeChat version transitions, alert acknowledgement and intake upload/metadata object identity must agree across their separate files.

Controlled preflight coverage is now mechanically compared with every API and Worker production-required setting and `.env.example`. Its names-only inventory rejects undeclared protected-workflow mappings and enforces the storage class for every required name: database URLs, request bodies and all Secret/Token/Key values must come from GitHub Secrets, while non-sensitive topology remains in Variables. It rejects surrounding whitespace before validation and enforces the same PostgreSQL TLS, placeholder/minimum-secret, canonical 32-byte Base64 address-key and Worker-tenant constraints as production startup and the address cipher itself, so ignored characters, padding or whitespace cannot make the reviewed configuration differ from the runtime value. API, Worker and preflight also reject the complete local/unspecified host boundary used by configured HTTPS and PostgreSQL endpoints, including `localhost` subdomains, IPv4 `0/8` and `127/8`, bracketed IPv6 loopback/unspecified addresses and IPv4-mapped IPv6 loopback forms. The protected workflow additionally binds configured `RELEASE_COMMIT` to the requested candidate SHA. Once the performance subset is present, preflight calls the real performance validator to reconcile candidate/deployed GHCR digests and reject unsafe paths, bodies, targets or report files before load. It then binds the publisher run to the current trusted-policy SHA, resolves exactly one unexpired Artifact ID, validates GitHub's Artifact digest over the downloaded ZIP, safely extracts the sole root manifest and requires exact normalized manifest equality. This prevents a green configuration precheck from hiding a deterministic runtime, performance-gate or image-provenance failure.

`pnpm controlled:inventory` derives a names-only provisioning manifest from that same protected workflow. A names-only account/server export can therefore be audited for exact Stage 47–50 secret, variable and external-file coverage without granting value access or treating configuration presence as suite evidence. The optional GitHub audit discards variable values and fails closed on wrong storage classes, ambiguous duplicate classes, malformed API data or a truncated name list.

## Execution order

1. Freeze and cleanly check out the candidate commit, run `pnpm controlled:preflight`, then use `pnpm controlled:prepare` to create a new candidate/deployment/environment-bound workspace. The initializer calculates the plan SHA-256 and creates the 11 suite directories and 47-artifact checklist without fabricating evidence or PASS decisions. Import only redacted external outputs through the generated non-overwriting `pnpm controlled:capture` commands.
2. Run the V5 zero-data inventory first. If it fails, stop and reinstate full migration engineering before any other release activity.
3. Run PostgreSQL, Worker and commerce suites against the exact candidate database.
4. Run identity/object intake, payment, plugin/GEO and performance suites in controlled pre-production.
5. Complete physical/WAL recovery, privacy propagation and alert acknowledgement.
6. Run official WeChat build/review/pilot/rollback last, then assemble `results.json` and execute `pnpm launch:gate` as a local precheck.
7. Use `pnpm controlled:stage-release` to create the exact 96-file upload staging directory; archive only that directory as the sole asset of a candidate-bound draft GitHub Release. The protected `verify-controlled-release.yml` workflow locks the Release ID and unique Asset ID, hashes the downloaded archive and rejects extra or missing package files before running trusted verification. The independent environment reviewer inspects the evidence before approval; the resulting attestation binds the immutable asset and workflow run as the final auditable verification record.

Failed attempts remain evidence. Do not reduce load, change the candidate, replace an artifact or broaden an identity to turn a failure green.
