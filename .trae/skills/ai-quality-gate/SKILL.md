## AI开发质量守门员执行流程

本 Skill 适用于：新功能开发、Bug 修复、代码重构、依赖升级、接口或数据库调整、测试、回归、代码审查、构建和发布任务。无论项目使用何种技术栈，以下流程必须遵守。

### 1. 读取测试规范
读取 `docs/TESTING_STANDARD.md` 和 `tests/TEST_MATRIX.md`，了解项目测试标准和现有测试用例。读取 `quality-gate.config.json` 确认项目已完成初始化（`initialized: true`），若未初始化则先按 `docs/PROJECT_INITIALIZATION.md` 完成初始化。

### 2. 影响分析
分析本次修改影响的功能、接口、数据库、用户角色和现有测试用例。明确：
- 受影响的模块和文件清单
- 受影响的 API 接口和数据模型
- 受影响的用户角色和权限
- 需要回归的现有测试用例

### 3. 基线测试
修改前运行相关已有测试，记录基线结果；如果无法运行，明确说明原因。基线结果作为回归对比依据。

### 4. 测试用例编写
- **新功能**：同步编写单元测试、接口测试和端到端测试。
- **Bug 修复**：先编写能够稳定复现 Bug 的失败测试用例，再修改代码。该复现测试修复后必须通过，并作为永久回归测试保留，不得删除。
- **重构**：保证现有测试全部通过，不降低覆盖率。

### 5. 测试执行
- 先运行相关新增/修改的测试用例，确认通过。
- 再运行适当范围的完整回归测试。

### 6. 质量检查
实际运行以下检查（通过 `npm run quality:gate` 或 `node scripts/quality-gate.mjs`）：
- lint（代码风格检查）
- 类型检查（TypeScript / 其他类型系统）
- 单元测试
- 接口测试
- 关键端到端测试
- 构建

### 7. 禁止事项
- 禁止删除或跳过测试
- 禁止降低断言标准
- 禁止修改正确业务规则以适应测试
- 禁止伪造测试结果
- 禁止用固定等待掩盖问题
- 禁止用 `--if-present` 让缺失的测试命令静默通过
- 禁止把"没有测试"显示为"测试通过"
- 禁止连接正式数据库、正式支付或真实用户数据运行测试

### 8. 测试失败处理
区分以下类型并根据证据处理：
- 业务 Bug：修复代码
- 测试错误：修正测试用例
- 环境错误：修复环境或标记跳过（需注明理由）
- 偶发测试：增加重试机制或标记不稳定

### 9. 未执行标注
没有实际执行的测试必须标注"未执行"，不得描述为通过。未执行项需说明原因和风险评估。

### 10. 最终报告
输出以下内容：
- 修改范围
- 新增/修改测试用例
- 实际执行命令
- 真实结果（含退出码）
- 失败项及处理
- 未覆盖风险
- 人工验收项

### 详细标准
详细测试标准请参考 `docs/TESTING_STANDARD.md`。项目初始化指引见 `docs/PROJECT_INITIALIZATION.md`。
